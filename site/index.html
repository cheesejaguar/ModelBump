One model, many spellings

Every slug is read as a vendor, a model line and a version. A bump moves along the version and writes the result back in the same format, so code that talks to Bedrock keeps talking to Bedrock.

Exact IDs only

Detection uses a catalog of real model IDs from OpenRouter and the vendors. claude-opus-5 never matches inside claude-opus-5-5, and an ID ModelBump doesn't know is left alone.

No invented IDs

Replacements are looked up, never pattern-built. If the newer model doesn't exist in your format (say, no Bedrock id yet), the reference stays put and the plan says why.

One pull request per model

Every place that names Claude Opus 5 moves together, with prices, release dates and the vendor's migration notes in the PR. Close it to skip that release.

Choose how far a model moves

Set a strategy for the whole repository or per path. Claude stays Claude, GPT stays GPT, and open-weight models swap only for open-weight models.

What it leaves alone

Tested against aider, LiteLLM, the Vercel AI SDK, the OpenAI Agents SDK and Anthropic's cookbooks before release. A model ID is only rewritten where it is a choice your code makes.

  • Comments and prose. # was gpt-4o before March stays true. Markdown code blocks and inline code are still updated.
  • Model lists. Registries, price tables, leaderboards and docs that name many models, and slugs used as table keys.
  • History. Changelogs, blog posts, recorded API cassettes, test fixtures, snapshots and data files.
  • Your edits. Push a commit to a ModelBump branch and it stops touching that branch. Close a PR and that release is skipped.
  • Lines you pin. Add # modelbump: ignore to a line, or ignore rules to the config.

Conditions like if model == "claude-opus-5" are still updated, and the pull request lists them so you can check the logic.

Questions

        

        

          

            Will a newer model change how my app behaves?
            
It can: output style, tool use and accepted parameters change between releases. That's why ModelBump opens pull requests instead of committing. Each one links the vendor's migration notes, and your tests and evals decide whether to merge.

          

          

            Do I need any API keys?
            
No. The model catalog comes from OpenRouter's public list and a curated file of first-party IDs. Optional keys add more: ANTHROPIC_API_KEY and OPENAI_API_KEY confirm first-party IDs, and ARTIFICIAL_ANALYSIS_API_KEY supplies benchmark scores for cost-optimized.

          

          

            Is my code sent anywhere?
            
No. ModelBump runs in your GitHub Actions runner and only downloads public model lists. The demo on this page runs entirely in your browser.

          

          

            How is this different from Dependabot or Renovate?
            
They update packages declared in manifests. A model ID is a string in your source, config or .env, in one of several host formats, so it needs its own detection and its own idea of what "newer" means.

          

          

            Which providers are covered?
            
Anthropic, OpenAI, Google, xAI, Meta, Mistral, and the Chinese open-weight labs: DeepSeek, Qwen, Moonshot (Kimi), Z.ai (GLM), MiniMax, Xiaomi (MiMo), StepFun, Tencent and Baidu. Models from other labs are left alone.

          

          

            Does it work in monorepos and private repositories?
            
Yes. Use the action's path input for a subdirectory, or updates rules in the config to set a strategy per path. Private repositories work the same way.

          

          

            Can I use it as a check instead of a bot?
            
Yes. Run the action with command: plan and fail-on-updates: true on pull requests. Each outdated ID shows up as an annotation on the workflow run.
